Учебник · от тензора до обученной модели

Шесть строк, которые повторяются миллион раз

PyTorch — библиотека для обучения нейросетей. Представьте машину с миллионами ручек-настроек: она делает предположение, ошибается, и каждая ручка чуть поворачивается в сторону меньшей ошибки. Вся библиотека существует, чтобы этот поворот происходил автоматически. Вот как выглядит сердце любой обучающей программы — нажмите на строку, чтобы понять, что она делает.

§ 02 · данные в памяти

Тензор — это просто сетка чисел

Число, список, таблица, стопка таблиц — всё это тензоры разной размерности. По сути это массив NumPy с двумя суперспособностями: его можно отправить на видеокарту и он умеет запоминать, как был получен (об этом — в следующем разделе).

РазмерностьКак называютПример
0Dскалярзначение функции потерь: 3.14
1Dвекторэмбеддинг слова: [0.2, -1.1, 0.7]
2Dматрицабатч признаков: (64, 784)
3Dтензоркартинка: (3, 224, 224) — каналы, высота, ширина
4Dтензорбатч картинок: (64, 3, 224, 224)

Broadcasting — почему формы «сами» подходят

Если у тензоров разные формы, PyTorch пытается растянуть меньший вдоль недостающих осей. Правило читается справа налево: оси совпадают, либо одна из них равна 1, либо её нет вовсе.

python
batch = torch.randn(64, 3)      # 64 примера по 3 признака
bias  = torch.tensor([1., 2., 3.])

out = batch + bias              # bias растянут на все 64 строки -> (64, 3)

col = torch.randn(64, 1)
out = batch * col               # (64,3) * (64,1) -> (64,3): столбец растянут по признакам

# А вот это упадёт: 3 и 4 несовместимы
# torch.randn(64, 3) + torch.randn(4)

Изменение формы

python
t = torch.randn(64, 1, 28, 28)      # батч чёрно-белых картинок

t.view(64, -1)        # -1 = «посчитай сам» -> (64, 784). Без копирования, но нужен непрерывный тензор
t.reshape(64, -1)     # то же, но скопирует, если иначе нельзя. Безопаснее
t.flatten(1)          # схлопнуть всё начиная с оси 1 -> (64, 784)
t.squeeze(1)          # убрать ось размера 1 -> (64, 28, 28)
t.unsqueeze(0)        # добавить ось -> (1, 64, 1, 28, 28)
t.permute(0, 2, 3, 1) # переставить оси -> (64, 28, 28, 1)

§ 03 · главная магия

Autograd: как ошибка возвращается назад

Пометьте тензор как requires_grad=True — и PyTorch начнёт тихо записывать каждую операцию с ним в граф: кто из кого получился. Когда вы вызовете .backward() на итоговом числе, библиотека пройдёт по этому графу назад и для каждого помеченного тензора посчитает производную. Это то самое, что вручную для миллиона параметров не посчитает никто.

python · минимальный пример
w = torch.tensor(2.0, requires_grad=True)
x = torch.tensor(3.0)

y = w * x + 1        # граф записан: y <- (+1) <- (*) <- w, x
y.backward()         # идём назад

print(w.grad)        # tensor(3.) — потому что dy/dw = x = 3
print(x.grad)        # None — x не помечен, для него ничего не считалось
Граф вычислений вживую граф собран

Один нейрон учится предсказывать y = 5 по входу x = 2. Двиньте ползунки, прогоните проход вперёд, затем назад — и сделайте шаг оптимизатора. Синее — значения, идущие вперёд. Малиновое — градиенты, идущие назад.

потери L—

шагов сделано0
история потерь

Тот же граф в коде — обратите внимание, что PyTorch считает ровно те же числа, что вы видели в белых прямоугольниках:

python · тот же нейрон
x, y_true = torch.tensor(2.0), torch.tensor(5.0)
w = torch.tensor(0.5, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)

for step in range(30):
    z = w * x + b            # предсказание
    loss = (z - y_true) ** 2 # потери

    if w.grad is not None:   # градиенты НАКАПЛИВАЮТСЯ — чистим
        w.grad.zero_(); b.grad.zero_()

    loss.backward()          # считаем dL/dw и dL/db

    with torch.no_grad():    # шаг руками, вне графа
        w -= 0.05 * w.grad
        b -= 0.05 * b.grad

print(w.item(), b.item(), loss.item())

Четыре инструмента, которые нужны каждый день

ЧтоЗачем
requires_grad=TrueПометить тензор как обучаемый. У параметров модели включено автоматически.
.backward()Пройти по графу назад. Вызывается на скаляре (одном числе), обычно на потерях.
with torch.no_grad():Не строить граф вообще. Ускоряет и экономит память — используйте при валидации и инференсе.
.detach()Вырезать тензор из графа: значение то же, история забыта. Удобно, когда сохраняете промежуточные результаты.
откуда берётся «нет графа» После .backward() граф освобождается. Второй вызов на том же результате выдаст ошибку про backward through the graph a second time — почти всегда это значит, что вы забыли пересчитать forward внутри цикла.

§ 04 · сборка модели

nn.Module — конструктор из готовых блоков

Модель в PyTorch — это класс, наследник nn.Module. В __init__ вы создаёте слои, в forward описываете, как данные через них проходят. Всё остальное — сбор параметров, перенос на GPU, сохранение — вы получаете бесплатно.

python
import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, in_dim=784, hidden=128, out_dim=10):
        super().__init__()               # обязательно, иначе ничего не заработает
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden),   # y = xW + b
            nn.ReLU(),                   # нелинейность: max(0, x)
            nn.Dropout(0.2),             # регуляризация: гасим 20% нейронов при обучении
            nn.Linear(hidden, out_dim),
        )

    def forward(self, x):
        x = x.flatten(1)                 # (B, 1, 28, 28) -> (B, 784)
        return self.net(x)               # ЛОГИТЫ, без softmax — так надо для CrossEntropyLoss

model = MLP()
print(model)                                       # красивое дерево слоёв
print(sum(p.numel() for p in model.parameters()))  # сколько всего «ручек»
важная привычка Вызывайте model(x), а не model.forward(x). Первый вариант дополнительно запускает хуки PyTorch; второй молча их пропускает и однажды сломает вам отладку.

Слои, которые встречаются чаще всего

СлойДля чего
nn.Linear(in, out)Полносвязный слой. База всего.
nn.Conv2d(in_ch, out_ch, k)Свёртка для изображений.
nn.ReLU(), nn.GELU()Нелинейности. Без них стопка Linear схлопывается в один Linear.
nn.BatchNorm2d, nn.LayerNormНормализация — стабилизирует и ускоряет обучение.
nn.Dropout(p)Борьба с переобучением. Активен только в режиме train().
nn.Embedding(n, dim)Таблица векторов: индекс → вектор. Основа работы с текстом.
nn.Sequential(...)Контейнер: пропускает вход через слои по очереди.

§ 05 · чему и как учить

Функции потерь и оптимизаторы

Функция потерь отвечает на вопрос «насколько плохо», оптимизатор — на вопрос «куда крутить». Выбор из обоих списков почти всегда очевиден по типу задачи.

ЗадачаФункция потерьЧто подавать
Регрессияnn.MSELoss()Предсказание и цель одинаковой формы
Классификация, N классовnn.CrossEntropyLoss()Логиты (B, N) и индексы классов (B,) типа long
Бинарная классификацияnn.BCEWithLogitsLoss()Логиты и цели 0/1 одинаковой формы
Регрессия с выбросамиnn.SmoothL1Loss()Как MSE, но менее чувствительна к выбросам
ловушка №1 у новичков CrossEntropyLoss уже содержит внутри softmax. Если добавить nn.Softmax() последним слоем модели, вы примените его дважды — модель будет учиться, но заметно хуже, и вы долго не поймёте почему.
python
import torch.optim as optim

loss_fn = nn.CrossEntropyLoss()

# AdamW — разумный выбор по умолчанию почти для всего
optimizer = optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)

# SGD с моментом — классика, часто даёт лучший финальный результат в CV
# optimizer = optim.SGD(model.parameters(), lr=0.1, momentum=0.9)

# Планировщик постепенно снижает шаг обучения
scheduler = optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=10)

Скорость обучения (lr) — самая важная настройка из всех. Слишком большая — потери прыгают или улетают в nan. Слишком маленькая — обучение ползёт. Разумные стартовые значения: 1e-3 для Adam/AdamW, 0.1 для SGD с моментом.

§ 06 · конвейер

Dataset и DataLoader

Dataset отвечает на вопрос «дай мне пример номер i». DataLoader оборачивает его: собирает батчи, перемешивает, грузит в несколько потоков параллельно с обучением. Свой датасет — это ровно три метода.

python
from torch.utils.data import Dataset, DataLoader

class MyDataset(Dataset):
    def __init__(self, X, y):
        self.X, self.y = X, y

    def __len__(self):
        return len(self.X)              # сколько всего примеров

    def __getitem__(self, i):
        return self.X[i], self.y[i]     # один пример: вход и ответ

ds = MyDataset(torch.randn(1000, 20), torch.randint(0, 2, (1000,)))

loader = DataLoader(
    ds,
    batch_size=64,      # по сколько примеров за раз
    shuffle=True,       # перемешивать каждую эпоху — для train ДА, для val НЕТ
    num_workers=2,      # процессов на подготовку данных
    drop_last=True,     # выбросить последний неполный батч
)

for xb, yb in loader:
    print(xb.shape, yb.shape)   # torch.Size([64, 20]) torch.Size([64])
    break

§ 07 · всё вместе

Полный рабочий пример

Классификация рукописных цифр MNIST. Этот файл можно скопировать целиком и запустить — он скачает данные сам. Здесь собрано всё из предыдущих разделов; структуру этого скрипта вы потом будете переиспользовать почти без изменений.

python · train.py
import torch
import torch.nn as nn
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

# ---------- 1. Устройство ----------
device = "cuda" if torch.cuda.is_available() else "cpu"
torch.manual_seed(0)                     # воспроизводимость

# ---------- 2. Данные ----------
tf = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.1307,), (0.3081,)),
])
train_ds = datasets.MNIST("./data", train=True,  download=True, transform=tf)
test_ds  = datasets.MNIST("./data", train=False, download=True, transform=tf)

train_loader = DataLoader(train_ds, batch_size=128, shuffle=True)
test_loader  = DataLoader(test_ds,  batch_size=512, shuffle=False)

# ---------- 3. Модель ----------
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Flatten(),
            nn.Linear(784, 256), nn.ReLU(), nn.Dropout(0.2),
            nn.Linear(256, 10),
        )
    def forward(self, x):
        return self.net(x)

model = MLP().to(device)

# ---------- 4. Потери и оптимизатор ----------
loss_fn   = nn.CrossEntropyLoss()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)

# ---------- 5. Одна эпоха обучения ----------
def train_epoch():
    model.train()                        # включаем dropout и обновление batchnorm
    total = 0.0
    for x, y in train_loader:
        x, y = x.to(device), y.to(device)

        pred = model(x)
        loss = loss_fn(pred, y)

        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

        total += loss.item() * x.size(0) # .item() -> обычное число, граф не держим
    return total / len(train_loader.dataset)

# ---------- 6. Проверка ----------
@torch.no_grad()                         # градиенты тут не нужны
def evaluate():
    model.eval()                         # выключаем dropout
    correct = 0
    for x, y in test_loader:
        x, y = x.to(device), y.to(device)
        pred = model(x)
        correct += (pred.argmax(dim=1) == y).sum().item()
    return correct / len(test_loader.dataset)

# ---------- 7. Поехали ----------
for epoch in range(1, 6):
    loss = train_epoch()
    acc  = evaluate()
    print(f"эпоха {epoch}  потери {loss:.4f}  точность {acc:.2%}")

torch.save(model.state_dict(), "mnist_mlp.pt")
чего ожидать После пяти эпох точность будет около 97–98%. Если на первой эпохе потери не падают — почти наверняка дело в скорости обучения или в забытом zero_grad().

model = model.to(device)          # модуль переносится НА МЕСТЕ, но так писать безопаснее

# Обратно на CPU — например, чтобы отдать в NumPy или matplotlib
values = pred.detach().cpu().numpy()
смешанная точность На современных картах обучение можно почти удвоить по скорости, считая часть операций в float16. Это несколько строк вокруг обычного цикла — ищите torch.amp.autocast и GradScaler, когда базовый цикл уже работает.

§ 09 · после обучения

Сохранение и загрузка

Сохраняйте state_dict — словарь весов, а не объект модели целиком. Файл с целым объектом привязан к вашей структуре папок и версии кода, и рано или поздно перестанет открываться.

python
# Сохранить
torch.save(model.state_dict(), "model.pt")

# Загрузить: сначала создаём такую же архитектуру, потом вливаем веса
model = MLP()
model.load_state_dict(torch.load("model.pt", map_location=device))
model.eval()                       # для инференса — обязательно

# Чекпоинт, чтобы продолжить обучение с того же места
torch.save({
    "epoch": epoch,
    "model": model.state_dict(),
    "optim": optimizer.state_dict(),
}, "ckpt.pt")

§ 10 · грабли

Ошибки, на которых спотыкаются все

Забыт optimizer.zero_grad()

Градиенты накапливаются со всех прошлых батчей. Потери либо стоят на месте, либо взрываются. Проверяйте это первым.

Softmax перед CrossEntropyLoss

Внутри функции потерь softmax уже есть. Модель должна возвращать сырые логиты.

Нет model.eval() при проверке

Dropout продолжает гасить нейроны, BatchNorm обновляет статистику — метрики получаются хуже реальных и нестабильны.

Валидация без torch.no_grad()

Строится ненужный граф: память течёт, всё работает вдвое медленнее.

Накопление тензора вместо .item()

total += loss держит весь граф в памяти. Пишите total += loss.item().

Данные и модель на разных устройствах

Ошибка вида «expected all tensors to be on the same device». Проверьте .to(device) и там, и там.

Неверный dtype для меток

CrossEntropyLoss ждёт целочисленные индексы классов (long), а не float и не one-hot.

view() на непрерывном тензоре

После permute или transpose используйте reshape либо .contiguous().view(...).

Куда двигаться, когда цикл заработал

  • torch.compile(model) — одна строка, которая часто даёт заметное ускорение без изменений в коде.
  • Смешанная точность (torch.amp) — быстрее и экономнее по памяти на современных GPU.
  • Дообучение готовых моделей — torchvision.models для картинок, Hugging Face Transformers для текста. Учить с нуля почти никогда не нужно.
  • Логирование — TensorBoard или Weights & Biases вместо print: кривые обучения покажут проблему раньше, чем цифры.
  • Несколько GPU — DistributedDataParallel, когда одна карта перестала помещать модель или данные.
  • Меньше рутины — PyTorch Lightning или Hugging Face Accelerate убирают повторяющийся код цикла.

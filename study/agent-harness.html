Harness, framework, runtime — где что

В 2025 у этого слоя не было даже устоявшегося названия. К 2026 сложилась трёхуровневая модель — её удобно держать в голове, разбирая любой проект. Формулировка принадлежит Харрисону Чейзу (CEO LangChain): «LangGraph — это runtime, LangChain — абстракция, Deep Agents — harness».

◇

Framework абстракция

Строительные блоки и способ описать логику: цепочки, роли, промпты, парсеры вывода. Сам по себе ничего не «крутит» — даёт словарь.

↻

Runtime исполнение

Движок, который гоняет цикл: состояние, ветвления, циклы, human-in-the-loop, персистентная память. Здесь живёт граф выполнения.

▣

Harness боевая обвязка

Всё, что нужно одному агенту, чтобы действовать самому: выполнение инструментов, песочница, память, управление контекстом, guardrails, трейсинг. Frameworks композируют агентов — harness их запускает.

≡

Простое правило разделения

Frameworks компонуют агентов (как их собрать и связать). Harness исполняет одного агента (как он живёт в бою: инструменты, границы, контекст). На практике граница размыта — LangGraph работает и как runtime, и как harness, а Pydantic AI в v2.0 встроил harness прямо в ядро.

01

Как читать эту карту

Решения делятся на два больших лагеря. Выбор между ними — это в первую очередь выбор степени контроля и уровня привязки к экосистеме, а не «кто мощнее».

⊞

Граф-ориентированные graph-based

Вы сами рисуете граф шагов: узлы, рёбра, ветвления. Максимум контроля и предсказуемости, выше порог входа. Сюда: LangGraph, Microsoft Agent Framework, Google ADK 2.0.

↻

Модель-ведомые model-driven loop

Цикл ведёт сама модель, решая на каждом шаге, что делать. Меньше кода, меньше контроля. Сюда: OpenAI Agents SDK, Claude Agent SDK, Strands, smolagents, Pydantic AI.

02

Разбор решений

Тринадцать проектов, которые реально используют в 2026. Звёзды GitHub даны как порядок величины на середину года — они устаревают за недели, так что ориентируйтесь на них грубо, а не буквально.

LangGraph Python · JS/TS

LangChain MIT

Дефолт для сложных Python-воркфлоу. Агент как явный граф состояний: вы сами описываете узлы и переходы, есть циклы, персистентная память и human-in-the-loop. В связке идут Deep Agents (собственно harness для долгих задач) и LangSmith (трейсинг, оценки, деплой).

▲ сильные стороны
  • Полная видимость границы «агент ↔ модель»
  • Явный контроль состояния и ветвлений
  • Зрелая экосистема, 1000+ интеграций
▼ цена
  • Высокий порог входа в начале
  • Многословность для простых задач
  • Легко утонуть в индирекции LangChain
Брать когда: сложные production-воркфлоу на Python, где нужен полный контроль над каждым шагом и состоянием.

Claude Agent SDK Python · TS

Anthropic batteries-included

Вырос напрямую из Claude Code. Принцип: «дай агенту компьютер» — shell, файловая система, веб, как у человека. 8 встроенных инструментов из коробки (Bash, Read/Write/Edit, Glob/Search) плюс субагенты и поддержка MCP. Единственный SDK, где агент напрямую управляет ОС.

▲ сильные стороны
  • Работает сразу, без ручной обвязки инструментов
  • Hooks для тонкого контроля поведения
  • Мульти-облако: Bedrock, Vertex, Azure Foundry
▼ цена
  • Заточен под модели Claude
  • Меньше «конвейерных» абстракций для мульти-агента
  • Биллинг менялся в 2026 — следите за условиями
Брать когда: terminal-first работа с кодом и файлами на моделях Claude, нужен контроль через hooks и экосистема MCP.

OpenAI Agents SDK Python

OpenAI MIT ★ ~28k

Лёгкий фреймворк с минимумом абстракций. Строится вокруг двух идей: handoffs (передача разговора между специализированными агентами) и guardrails (слои валидации входов/выходов). Автоматический трейсинг каждого прогона. Провайдер-агностик: 100+ моделей через совместимый endpoint.

▲ сильные стороны
  • Низкий порог входа, минимум магии
  • Встроенные guardrails и трейсинг
  • Hosted-инструменты, голосовые агенты
▼ цена
  • Глубже всего интегрирован с моделями OpenAI
  • Меньше контроля, чем у граф-подхода
  • Роутинг через handoffs — не универсален
Брать когда: нужны минимальные абстракции, встроенные guardrails/трейсинг и голосовые сценарии, стек завязан на OpenAI.

Google ADK 2.0 Python · Java · Go

Google Apache 2.0 ★ ~20k

Open-source спутник Vertex AI Agent Builder. Версия 2.0 (стабильна с мая 2026) сменила модель исполнения с LLM-ведомой на граф-based: детерминированный Workflow Runtime, структурированный Task API для мульти-агентной делегации, протокол A2A для общения агентов между фреймворками.

▲ сильные стороны
  • Детерминированное исполнение вне решений LLM
  • Нативная интеграция с Cloud Run и Vertex
  • Grounding через Google Search
▼ цена
  • 2.0 ломает совместимость с 1.x (сменилась вся модель)
  • Экосистема уже LangChain вне Google Cloud
  • Кривая обучения растёт с завязкой на GCP
Брать когда: вы в экосистеме Google Cloud и нужна LangGraph-альтернатива со встроенной инфраструктурой.

smolagents Python

Hugging Face Apache 2.0 ★ ~26k

Минимализм: ~1000 строк ядра — легче всего понять и изменить. Ключевая фишка — CodeAgent: агент генерирует Python-код вызова инструментов, фреймворк исполняет его в песочнице и возвращает результат. Такой подход снижает число вызовов LLM примерно на 30% против классического function-calling.

▲ сильные стороны
  • Прозрачное ядро, всё читается за вечер
  • Песочницы: E2B, Modal, Docker, Pyodide+Deno
  • Model-agnostic через LiteLLM, есть локальные модели
▼ цена
  • Меньше готовых production-фич
  • Мульти-агент — только через иерархии агентов
  • Исполнение кода требует аккуратной песочницы
Брать когда: хотите лёгкий, понятный до дна harness и подход «агент пишет код», в т.ч. на локальных моделях.

Pydantic AI Python

Pydantic MIT v2.0 harness-first

Type-safe подход для Python-сервисов. В версии 2.0 (июнь 2026, ломающая) переехал на harness-first дизайн с «capabilities» как ядром: единый композируемый блок, который связывает инструменты, hooks, инструкции и настройки модели. Когда фреймворк встраивает harness в ядро — это лучший признак, что слой стал реальностью.

▲ сильные стороны
  • Строгая типизация и валидация на входе/выходе
  • 50+ capabilities в harness-документации
  • Естественно ложится в типизированные сервисы
▼ цена
  • v1→v2 — ломающий переход (осторожно с обещаниями стабильности)
  • Только Python
  • Молодой harness-слой ещё устаканивается
Брать когда: типобезопасные Python-сервисы, где важна валидация и композируемые capabilities.

Strands Agents Python

AWS model-driven

Провайдерский SDK в модель-ведомом лагере: меняет часть контроля на простоту. Хороший выбор, если вы уже привязаны к одной модельной экосистеме и не хотите вручную собирать граф.

▲ сильные стороны
  • Простой цикл, ведомый моделью
  • Меньше кода на старте
  • Ложится в экосистему AWS
▼ цена
  • Меньше контроля над шагами
  • Привязка к экосистеме
  • Экосистема меньше, чем у LangGraph
Брать когда: нужен простой model-driven агент внутри стека AWS.

Microsoft Agent Framework .NET · Python

Microsoft GA 1.0 · апр 2026

Наследник AutoGen и Semantic Kernel, слитых в один SDK (GA с апреля 2026). Граф-ориентированный, с прицелом на enterprise: интеграция с Microsoft Foundry, обнаружение навыков через MCP (McpSkillsPlugin), защита от prompt injection, деплой в Azure Container Apps с наблюдаемостью.

▲ сильные стороны
  • Единый преемник двух зрелых проектов
  • Стабильный ритм релизов, enterprise-фокус
  • Встроенная безопасность и наблюдаемость
▼ цена
  • Лучше всего раскрывается в экосистеме Azure
  • Требует миграции с AutoGen
  • Граф-подход = выше порог входа
Брать когда: enterprise на .NET/Azure, нужен официальный преемник AutoGen с governance из коробки.

CrewAI Python

role-based ★ ~52k

Ролевая оркестрация: агенты с чёткими ролями (аналитик, писатель, ревьюер) в команде-«экипаже». Низкий порог входа — быстрее всего поднять мульти-агентную систему, если задача аккуратно раскладывается на роли.

▲ сильные стороны
  • Быстрый старт мульти-агентной системы
  • Интуитивная модель ролей
  • Большое активное сообщество
▼ цена
  • Меньше контроля на границе агент↔модель, чем у графа
  • Ролевая модель подходит не под всякую задачу
  • Сложнее отлаживать нестандартные потоки
Брать когда: задача раскладывается на чёткие роли и нужно быстро собрать работающий прототип.

Mastra · Vercel AI SDK TypeScript

TS-экосистема

Основной выбор для TypeScript. Если бэкенд и фронтенд на TS и вы не хотите тащить Python ради агентов — эти два проекта закрывают потребность нативно, без переключения стека.

▲ сильные стороны
  • Нативный TypeScript, один язык на весь стек
  • Хорошая интеграция с веб-фронтендом
  • Быстрый путь от прототипа к деплою
▼ цена
  • Экосистема агентов на TS моложе питоновской
  • Меньше готовых интеграций, чем у LangChain
  • Тяжёлый мульти-агент — не главный сценарий
Брать когда: весь продукт на TypeScript и агенты должны жить в том же стеке.

Agno Python

lightweight

Лёгкий Python-фреймворк, регулярно попадающий в обзоры 2026 как компактная альтернатива тяжёлым решениям. Ставка на скорость разработки и простоту при сохранении мульти-агентных сценариев.

▲ сильные стороны
  • Небольшой и быстрый в освоении
  • Меньше накладных абстракций
  • Подходит для быстрых прототипов
▼ цена
  • Сообщество меньше мейнстримных
  • Меньше готовых production-гарантий
  • Проверяйте актуальность под свой кейс
Брать когда: нужен компактный Python-фреймворк без лишнего веса для быстрой сборки.

AutoGen Python · .NET

Microsoft maintenance ★ ~60k

Исторически самый звёздный фреймворк в обзоре. Но с конца 2025 — в режиме поддержки: только багфиксы и патчи безопасности, новых фич нет, дальше ведётся сообществом. Microsoft рекомендует переезд на Microsoft Agent Framework и публикует гайд по миграции.

▲ что осталось
  • Огромная база примеров и материалов
  • Существующие приложения продолжают работать
  • Проверенные паттерны мульти-агента
▼ почему осторожно
  • Нет новых фич — только поддержка
  • Официально рекомендован преемник
  • Двойное лицензирование (MIT код + CC-BY-4.0 контент)
Не начинать новое на нём. Для новых проектов — Microsoft Agent Framework. AutoGen оставьте существующим системам.
⚡

Про «вирусные» проекты и хайп

Летом 2026 в лентах гремели новые имена вроде self-hosted harness'ов, набиравших десятки тысяч звёзд за считанные дни. Звёзды — это внимание, а не зрелость. Прежде чем ставить такое в production, проверьте: частоту коммитов, ясность лицензии, наличие issue-триажа и живой ли безопасностный процесс. Быстрый рост звёзд сам по себе ничего не гарантирует.

04

Как выбрать под себя

Главный водораздел — язык и экосистема, а уже потом нужная степень контроля. Пройдите сверху вниз.

▸ На каком языке пишете?

TypeScript→Mastra / Vercel AI SDK не тащите Python ради агентов, если весь стек на TS
.NET→Microsoft Agent Framework официальный преемник AutoGen с enterprise-фичами
Python→ идём дальше ↓

▸ Привязаны к экосистеме модели?

Только Claude→Claude Agent SDK особенно для работы с кодом, файлами и доступом к ОС
Только OpenAI→OpenAI Agents SDK минимум абстракций, встроенный трейсинг и guardrails
Google Cloud→Google ADK 2.0 детерминированный граф + нативная инфраструктура Vertex
AWS→Strands Agents простой model-driven цикл в стеке AWS
Модель-агностик→ идём дальше ↓

▸ Что важнее для задачи?

Максимум контроля, сложный поток→LangGraph явный граф состояний, полная видимость каждого шага
Строгая типизация сервиса→Pydantic AI harness-first, валидация входов/выходов
Понять harness до дна / локальные модели→smolagents ~1000 строк ядра, подход «агент пишет код»
Быстро собрать мульти-агента по ролям→CrewAI низкий порог, если задача раскладывается на роли
◈

Трейсинг — отдельно от harness

Наблюдаемость стоит выбирать независимо. LangSmith (от LangChain) и Langfuse (open source) работают поверх почти любого стека: собирают трейсы, стоимость, латентность и качество ответов на каждом шаге. Ставьте это с первого дня — без трейсинга отладка агента превращается в гадание.

05

Грабли, на которые стоит наступить чужими ногами

Короткий чек-лист перед тем, как закоммититься в конкретный проект.

Ломающие мажорные версии

Pydantic AI (v1→v2) и Google ADK (1.x→2.0) в 2026 сменили саму модель исполнения. Обещание стабильности API — не гарантия. Закладывайте бюджет на миграцию и читайте changelog до апгрейда.

Лицензии сложнее, чем кажется

У AutoGen код под MIT, а примеры и документация — под CC-BY-4.0. Обзоры, называющие «одну лицензию», описывают половину. Проверяйте фактические файлы лицензий в репозитории, а не строчку на карточке.

Исполнение кода = песочница обязательна

CodeAgent-подход (smolagents) и любой агент с доступом к shell мощны, но опасны. Никогда не запускайте сгенерированный код без изоляции: E2B, Modal, Docker или WASM (Pyodide+Deno). Отдельно — защита от prompt injection.

Провайдерский SDK = мягкий lock-in

Claude Agent SDK, OpenAI Agents SDK, ADK, Strands раскрываются полнее всего внутри «своей» экосистемы. Это не плохо, но если завтра захотите сменить модель — заложите, что часть кода придётся переписать.

Начните со своего цикла на 60 строк

Прежде чем брать фреймворк, соберите минимальный harness сами: описание инструментов → цикл «модель ↔ вызов» → лимит шагов. Тогда любой проект из этого списка станет понятным — внутри все они делают ровно это.
